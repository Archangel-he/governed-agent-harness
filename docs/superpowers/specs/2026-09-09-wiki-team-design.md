# Unified Agent, Wiki Memory and Hierarchical Teams

Approved scope (2026-09-09): one reusable Agent core, extended by a Supreme -> Leader -> Member composition. Humans submit to Supreme; leaders assign and review member work; Supreme reviews team reports and produces final output. Role differences are plugins and authority, never three different kernels. Single-host Docker deployment; no new OS runners or multi-tenancy.

## Runtime and evidence
Preflight validates every binding before recording an execution. Lifecycle factory is called once; the exact validated instance is activated and disposed. Recovered unknown side effects are never replayed automatically. Source evidence is loaded from persisted execution logs, identity/version/input/environment verified, and evaluator identity plus memory release fixed in experiments. Attempt failure remains visible without masquerading as final failure; unknown effects always fail release. Whole-Agent attribution emits hypotheses with upstream/downstream evidence, not unsupported causal certainty.

## Memory
An Agent instance owns a Wiki. Optional Team and Supreme shared Wikis are separate namespaces. Plugins share scoped reads and propose changes; plugin scratch state is not knowledge. Immutable raw sources -> versioned Markdown pages and links -> immutable MemoryRelease. One local writer merges proposals with expected-release CAS. Each proposal includes source references and fact/hypothesis status; conflicts never silently overwrite pages. Reads cite release/page revisions. The execution pins release IDs; replay experiments use identical memory releases. A memory compiler is a normal plugin, not an extra permanent Agent. Initial navigation uses page index and keyword matching, no vector database.

## Teams
Persist hierarchy, assignment envelopes, idempotency keys, reports, acknowledgements and acceptance. Each role runs the same GovernedAgentRuntime with an AgentVersion. Coordinator capabilities are ordinary plugins; Team runtime validates role authority and task transitions. A2A means our durable internal protocol, not a claim to implement Google's external A2A specification. Root accepts human tasks; Supreme assigns to direct Leaders, Leaders assign to direct Members; reports return to the immediate parent. Cross-team requests are routed through Supreme. Members can report a need for rework; the parent creates a new assignment key and preserves the old report. Report submission does not equal acceptance. Parent reviewer runs as an Agent execution and must cite child result evidence. Persist before side effects, acknowledge after durable result, recover by request identity. Bound total tasks and cancellation propagation. A parent report is admissible only after all required child results are accepted.

## Deployment and developer UX
Docker deployment runs the application and its roles using the same code. Independent Agent identity/session/memory is mandatory; a separate container per role is a deployment option, not an invented prerequisite. No host-OS security work. Template exports AgentVersion, plugins, evaluator and optional memory reader/compiler; adding a new Agent changes no core files. Smoke demonstrates Supreme with two Leaders and their Members, Wiki read/propose/publish, source-backed attribution, experiment and final acceptance. Test mode uses deterministic providers; external model behavior is not claimed without a real test.
